# Публичные DNS и входные серверы

Сверено 2026-10-13 через публичный DNS-over-HTTPS и конфигурации Nginx на трёх серверах. Это перечень текущего состояния, а не команда на переключение записей. При изменении сервера сначала проверяются Nginx-маршрут, служба и HTTPS, затем меняется DNS.

## Активные записи

| Имена | Текущая A-запись | Входной узел | Что принимает |
|---|---|---|---|
| `vovan20.ru`, `www.vovan20.ru`, `hub.vovan20.ru`, `api.vovan20.ru`, `stage.vovan20.ru` | `89.125.168.13` | Германия (`de`) | Основной сайт и защищённый онлайн-хаб; API и stage имеют отдельные виртуальные хосты |
| `vpn.vovan20.ru` | `198.13.184.145` | Алматы (`198`) | VPN-вход Xray |
| `eeklera.online`, `www.eeklera.online`, `os.eeklera.online`, `sentra.vovan20.ru`, `shop.eeklera.online` | `198.13.184.145` | Алматы (`198`) | Текущие веб-виртуальные хосты и прокси-маршруты |
| `cools1s.ru`, `www.cools1s.ru` | `78.17.19.43` | Нидерланды (`78`) | Статический сайт |

Зоны `vovan20.ru` и `cools1s.ru` делегированы Selectel. Зона `eeklera.online` делегирована Reg.ru. Рабочие A-записи уже ведут на узел, где настроен входной виртуальный хост; перенос всех доменов на один IP сейчас не требуется и может отключить существующие VPN/сайты.

| `os.vovan20.ru` | Виртуальный хост на `198`; в публичном DNS ответ NXDOMAIN | Отдельно проверить страницу и сертификат; только затем добавлять A на `198.13.184.145`, если её нужно вернуть в интернет |
| `agents.vovan20.ru` | Виртуальный хост на `78`; маршрут указывает на порт `3456`, который не слушал по последней инвентаризации | Не публиковать до восстановления или удаления маршрута |
| `claw.vovan20.ru` | Имя есть в конфигурации `78`; публичного A-ответа нет | Проверить назначение и фактический маршрут, затем решить, нужен ли адрес |
| `cools1s.online`, `www.cools1s.online` | Nginx на `78` направляет на порт `3001`; служба не слушала по последней инвентаризации | Не публиковать до восстановления приложения |
| `kursis.ru`, `www.kursis.ru` | Статический маршрут настроен на `78`; публичный DNS отвечает NXDOMAIN | Проверить регистрацию/делегирование зоны и решить, нужен ли этот домен |

## Целевой порядок перемещения

Публичные сайты можно будет переносить на Германию по одному: сначала добавить на `de` рабочий HTTPS-маршрут и проверить его по временному адресу, затем сменить A-запись с сохранением TTL и предыдущего IP для отката. VPN-имя остаётся привязанным к выбранному VPN-узлу и меняется только после теста Xray с клиентом. Имена выключенных проектов не создаются в DNS, пока подтверждены сервис и владелец домена.

Проверка DNS в этом документе не заменяет внешнее подтверждение сертификата и доступности самого приложения. Документ нужно обновить после каждого согласованного DNS-переноса.

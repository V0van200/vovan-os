# Реестр доменов и доступа

Раздел «Домены и доступ» сопоставляет доменные имена из каталога проектов и активных конфигураций Nginx на `de`, `78` и `198`. Для каждого имени он показывает найденные проекты, сервер, TLS-приёмник, Nginx-маршруты и upstream, а также наличие `auth`-правила в данных Nginx. Приложение за reverse proxy может иметь собственную авторизацию; отсутствие Nginx `auth` само по себе не доказывает открытый доступ.

Сверка в `hub/site/domain-map.json` — это ожидаемые A-записи, использованные для безопасного сравнения. Онлайн API на сервере DE раз в минуту отдельно смотрит DNS с системного resolver, а для имён из `https_names` проверяет TLS и короткий `GET /`. HTTPS-запрос отправляется только если текущий DNS совпал с ожидаемым публичным IP; новый или ошибочный адрес отображается, но не опрашивается. «Защита входом» по-прежнему означает только найденное правило Nginx, а HTTP 401/403 показывает, что веб-сервер ответил страницей с требованием входа.

Проверки доступны из защищённого API `/admin/hub/api/domain-health`, не принимают произвольные домены и не меняют DNS, сертификаты или службы. На странице отображается последнее состояние, API обновляет его раз в минуту, интерфейс перечитывает каждые 30 секунд. История проверок и уведомления пока не сохраняются.

Имена, присутствующие только в каталоге проектов, тоже выводятся как «в каталоге, но не в Nginx». Это помогает отличить план/старую привязку от найденного входного виртуального хоста. Маршруты раскрываются по нажатию, чтобы список оставался понятным.

# Онлайн-основа хаба

Хаб остаётся веб-приложением по адресу https://vovan20.ru/admin/hub/. Рабочий адрес и источники данных находятся на серверах; папка на флешке не участвует в хранении или обновлении.

## API

hub/api/server.py — небольшой API на стандартной библиотеке Python. Он слушает только 127.0.0.1:3980. Внешний маршрут /admin/hub/api/ проходит через ту же Nginx auth_request, что и хаб. SSE отключает буферизацию в Nginx, чтобы события доходили до уже открытых страниц.

- GET /health — проверка процесса.
- GET /state — возраст снимков, настройки, личные проекты, задачи и служебные статусы проектов.
- GET /events — событие snapshot после появления нового серверного JSON; соединение поддерживает heartbeat и повторное подключение.
- PUT /preferences/<key> — разрешённые пользовательские настройки.
- PUT /custom-projects и PUT /tasks — серверное хранение личных проектов и задач.
- PUT /projects/<id> — статус жизненного цикла, видимость, избранное, следующий шаг и заметка.

SQLite-файл хранится в /data/vovan-os-hub/state/hub.sqlite3. Он создаётся с правами владельца процесса, а ежедневная копия проходит PRAGMA quick_check; сохраняются 14 последних архивов в /data/vovan-os-hub/backups/hub-api/.

## Частота данных

SSE сообщает об изменении JSON в течение нескольких секунд после его записи. Это устраняет ожидание следующего обновления страницы. Сейчас первичный сборщик на 78 запускается раз в минуту и обычно работает около 25 секунд. Поэтому SSE не ускоряет получение исходной метрики: отдельный этап должен разделить лёгкую проверку доступности и нагрузки (короткий интервал) и тяжёлую инвентаризацию проектов (реже). Интерфейс обязан показывать время и источник каждой метрики.

## Выкладка и откат

Статический сайт продолжает обновляться штатным vovan-os-hub-deploy. API-код получает отдельные релизы под /data/vovan-os-hub/api/releases/; таймер проверяет новый main после обычного обновления Git-зеркала и запускает health-check. При ошибке API-релиз переключается назад. Установочный сценарий ops/install-online-api.sh добавляет systemd units, защищённый Nginx маршрут и проверяет конфигурацию до reload. Перед правкой Nginx он создаёт резервную копию исходного файла.

Для ручного отката API использовать /usr/local/sbin/vovan-os-hub-api-rollback. База приложения резервируется независимо от кода.

Рабочий каталог Windows и флешка могут использоваться для просмотра копии, но они не являются источником истины и не нужны для работы онлайн-хаба.
